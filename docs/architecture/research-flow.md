# 調査画面の推奨手順と ③ の開閉

`/research/[storeId]` は、店舗の営業資産ができるまでを次の 3 手順で案内する (#300)。

```
① AI調査 → ② レビュー (採用した項目が基本情報に入る) → ③ 営業資産を生成
```

営業資産の生成が読むのは `store.basic_info` だけで、AI 調査の結果はレビューで採用して
初めて生成に使われる。手順の状態は `lib/domain/research-flow.ts` の
`getResearchFlowSteps` が主表示 run から導出し、見出し直下の手順表示
(`research-flow-steps.tsx`) と ③ の開閉はどちらもこの結果を使う。

## 推奨順序と任意操作を両立させる (#322)

③ は ①② を飛ばしても使える (「AI調査をせずに生成」「レビューせずに生成」)。
一方で、未到達の手順が最初から全部開いていると、いまの作業 (①②) から目が逸れる。
そこで次のように決めた。

- **初期表示は推奨順序に従う。** ①② が完了していなければ ③ の本文を閉じて始める。
  完了していれば開いて始める。
- **折りたたみを利用禁止の意味にしない。** 閉じていても見出しのボタンでいつでも開け、
  開けばそのまま生成できる。生成ボタンの有効・無効は開閉と無関係で、従来どおり
  API キー未設定と処理中だけが無効にする。
- **利用者の開閉を取り消さない。** 手動で開閉したら、ポーリングや再描画では変えない。

「①② の完了」は手順表示の ② が完了 (`done`) であることで判定する
(`isGenerateStepReached`)。レビューの未対応が 0 件でも、レビュー完了操作をしていなければ
完了ではない。判定を手順表示と共有するのは、「② 未着手と表示しているのに ③ が開いている」
といった食い違いを作らないためである。

### 状態の変化

開閉の規則は `SalesAssetDisclosure` (純関数) にまとめ、単体テストで固定している。

| きっかけ | 開閉 |
|---|---|
| ページを開いた | ①② 完了なら開く、未完了なら閉じる |
| `#sales-assets` へのリンクで来た | ①② 未完了でも開く (着地先が閉じていると導線が切れる) |
| 利用者が見出しのボタンを押した | 見えている状態の逆にする。以後はこの選択を優先する |
| ポーリング等の再描画 (到達状態が変わらない) | 変えない |
| ② を完了した (未到達 → 到達) | 開く。手動で閉じていても開き、次の作業へ進める |
| 再調査を始めた (到達 → 未到達) | 変えない。入力の途中で本文を隠さない |

自動で開くのは「② を完了した瞬間」だけで、自動で閉じることはない。② の完了は
利用者自身の操作の結果なので、手動の選択より次の手順への誘導を優先した。

## 実装上の決まり

- **閉じた本文はアンマウントしない。** `hidden` 属性で隠す。入力中の補足情報・追加指示・
  生成結果の未保存の編集を失わない。`display: none` になるので、隠れた入力欄やボタンへ
  Tab でフォーカスが入らず、支援技術にも読まれない。
- `Card.Body` は `flex` を持つが、Tailwind の preflight が `[hidden]` に `!important` 付きの
  `display: none` を当てるため隠れる。この前提は `sales-asset-section-css.test.ts` が固定する。
- **開閉ボタンは見出し (`h3`) の中の `button`。** `aria-expanded` と `aria-controls` で状態と
  対象を伝え、視覚的には先頭の山形アイコンの向きで示す。Enter / Space で開閉できる。
  `<details>` を使わないのは、見出しの意味を保ったまま右側に「基本情報 n / m 件を使用」を
  並べるためである。
- **`hidden="until-found"` は使わない。** ページ内検索で開ける利点はあるが、React 19.2 は
  この値をそのまま出力せず、Safari も未対応で、推奨されるフォールバック (常に展開) は
  「初期状態で閉じる」要件と両立しない。
- 閉じている間は見出しの下線を消す (Card の枠線と二重にしない)。`cn` は素の clsx なので、
  基底クラスへ打ち消しのクラスを素で並べず、`data-state` の状態 variant で消す
  (`components/ui/__tests__/class-conflicts.test.ts` の方針)。
- ハッシュはサーバーに届かないので、`useState` の初期化で `window.location` を読まない
  (ハイドレーションが食い違う)。`useSyncExternalStore` でサーバー値 (`false`) と実値を分ける。
  スクロールは従来どおり `ai-research-workbench.tsx` のマウント時 effect が行う
  (loading 境界越しのハッシュ遷移では Next.js のスクロールが空振りするため、#313)。

## AI 調査中の工程一覧 (#323)

① の実行中は、調査中カード (`research-progress-card.tsx`) が 4 工程
(店舗を確認 → Web情報源を検索 → 店舗情報を取得・分析 → 結果を整理) の進み具合を示す。
工程の状態は run の `stage` から導き、ポーリング (4 秒ごと) で切り替わる。

### 状態の表し方

状態はアイコンの形・文言・行の強調の 3 つで伝え、色とアニメーションは補助にとどめる。

| 状態 | アイコン | 文言 | 行 |
|---|---|---|---|
| 進行中 | 回転アイコン (`Loader2` + `motion-safe:animate-spin`) | 進行中 | `bg-primary/10` で強調し、工程名を太字。`aria-current="step"` |
| 完了 | チェック (`Check`、`bg-success-soft` / `text-success-on-soft`) | 完了 | - |
| 未着手 | 枠線だけの円 (控えめに) | 未着手 | 工程名を `text-muted-foreground` |

- **上部の手順表示と同じ部品・トークンを使う。** 回転アイコン・チェック・円の大きさ
  (`size-5` の円に `size-3` のアイコン) と色の対を `research-flow-steps.tsx` に揃え、
  画面の中で「実行中」の見た目を 1 種類にする。
- **動きを減らす設定では回転させない。** `motion-safe:` で回転を付けるので、
  `prefers-reduced-motion: reduce` では静止した `Loader2` になる。それでも形がチェック・円と違い、
  「進行中」の文言と行の強調が残るため、状態は失われない。
- **アイコンは `aria-hidden`。** 状態は隣の文言で読み上げる。

### 配置

- **工程名に状態を埋め込まない。** 「店舗情報を取得・分析中」ではなく「店舗情報を取得・分析」とし、
  状態は別の文言で添える。未着手の工程に「〜中」と出る食い違いを防ぐ。
- **状態は工程名のすぐ右に置く。** カードの右端へ寄せると、広い画面で工程名と状態の距離が開き、
  対応を目で追えなくなる。工程名と状態は `flex-wrap` で並べ、狭い幅では状態だけが次の行へ
  折り返す (工程名を省略しない)。
- **補助情報は一覧の下に区切ってまとめる。** 経過時間・目安 (3〜5分)・目安超過の説明・
  「このページを離れても調査は継続されます。」は、境界線の下に小さな文字で並べる。

### 回転を残さない

工程一覧を描画するのは期限前の running のときだけである。失敗 (`ResearchFailedCard`)・
成功 (レビュー)・期限超過 (時間超過の案内) では一覧ごと消えるため、終わった処理に
回転アイコンが残らない。上部の手順表示も #324 の表示契約で同じ扱いにしている。

## 確認方法

- 単体: `lib/domain/__tests__/research-flow.test.ts` (到達判定・開閉の遷移)、
  `sales-asset-section-render.test.tsx` (初期の開閉と、閉じても本文が描画されること)
- E2E: `e2e/research-sales-asset-disclosure.spec.ts` (閉じて始まる・フォーカスが入らない・
  キーボード開閉・入力の保持・`#sales-assets` で開く)。seed の店舗は run を持たないため、
  E2E は未調査の店舗だけを扱う
- 工程一覧 (#323): 単体は `research-progress-card-render.test.tsx` (stage ごとの回転・強調・文言、
  工程名と状態の分離、期限超過で一覧が消えること)。E2E は `e2e/research-failure.spec.ts`
  (running の run を E2E 用 DB に書き込み、`stage` を進めると回転と「進行中」が移ること、
  失敗・期限超過で一覧が消えること)
