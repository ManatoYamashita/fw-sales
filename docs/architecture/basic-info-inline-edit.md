# 店舗の調査情報のインライン編集 (#335)

店舗詳細の基本情報タブにある「店舗の調査情報」カード (基本情報 53 項目、`stores.basic_info`) の表示と編集の契約。
実装は `app/(main)/stores/[id]/_components/basic-info-fields-card.tsx` (Server) と `basic-info-field-row.tsx` (Client)。

## この場所の役割

営業資産 (強み・弱み・架電スクリプトなど) を生成するときの入力を蓄える場所で、生成結果を表示する場所ではない。
値は次の経路で入り、AI 調査が終わっただけで全項目が埋まるわけではない。カード冒頭の文でこれを示す。

| 経路 | 保存される `filled_by` | 確信度・出典 |
| --- | --- | --- |
| AI 調査の結果を調査レビューで採用 (`buildAdoptedBasicInfoField`) | `manual` | 持つ (編集して採用した値は持たない) |
| エリア検索から登録 (`placeResultToBasicInfo`) | `places` | 持たない |
| このカードで直接入力 (`updateBasicInfoFieldAction`) | `manual` | 持たない |

採用も直接入力も `filled_by="manual"` なので、由来は `describeBasicInfoOrigin` (根拠の有無) で見分ける。
画面では「AI調査の結果をレビューで採用」「人が入力した値 (調査レビューで編集して採用した値を含む)」「エリア検索」と出す。

## 1 項目の構造

各項目は「項目名 / 値 / 信頼度」の 1 行。カード内の `@container` で、幅 `@2xl` (672px) 以上は 3 列 (項目名・値・信頼度の基準線をそろえる)、それ未満は 1 行目に項目名と信頼度、2 行目に値を置く。
DOM の順序は 項目名 → 信頼度 → 値で、信頼度はフォーカスを受けないためタブ順に影響しない。

- 値は最初から入力欄。短い項目 (`SINGLE_LINE_KEYS`: 屋号・オープン日・料理ジャンル・電話番号・階層・口コミ評価・口コミ件数) は `Input`、それ以外は `Textarea`。保存済みの値に改行があれば短い項目でも `Textarea` (Input は改行を落とすため)。
- `Textarea` は `field-sizing: content` で内容に合わせて伸びる。未対応ブラウザでは `rows` の目安 (1〜8 行) で開く。
- 未入力は入力欄のプレースホルダ「未入力」で示す。取得区分 C の項目は「未入力（店主へのヒアリングで確認）」。
- 出典・引用・由来・取得区分・更新日時 (日本時間に固定) は項目ごとの「根拠・詳細」(`<details>`) に畳む。値も質問も無い項目には出さない。

## 信頼度

判定は `lib/domain/basic-info-trust.ts` が持つ。規則と色は `docs/architecture/color-tokens.md` の「信頼度の 3 色」を参照。
値を変更して未保存の間は、保存済みの値の信頼度を出さず「未保存」と出す。保存直後 (再取得の前) は、人が直した値に元の確信度を出さないよう「未評価」として扱う。

## 保存・取消

- 値を変えた項目にだけ、入力欄の直下へ「保存」「取消」を出す。変更の判定は前後の空白を落として比べる (保存側も trim するため、空白だけの変更で根拠を消さない)。
- 空欄にすると「空欄のまま保存すると未入力に戻ります。」と入力欄の近くに出す。
- フォーカスが外れただけでは保存も破棄もしない。未保存の変更を残したままカテゴリを閉じると、カテゴリの見出しに「未保存の変更あり」を出す (`:has([data-unsaved])`)。
- 取消は保存済みの値へ戻し、入力欄へフォーカスを戻す。値・信頼度・出典は変えない。
- 保存は `updateBasicInfoFieldAction` を `runAction` 経由で呼ぶ (#327)。成功・失敗はトースト (`role="status"`) が読み上げる。
- 保存中は保存ボタンに `pending` (#326) を渡して「保存中」とスピナーを出し、取消は `disabled`、入力欄は `readOnly`。同じ項目への二重送信を防ぐ。
- 保存できたら入力欄へフォーカスを戻し、保存の遷移が終わってから `router.refresh()` する。遷移の中で呼ぶと再取得の遷移が束ねられ、再取得が終わるまで「保存中」が消えない (dev で 10 秒近く残った)。
- Action は店舗詳細・一覧のタグを `updateTag` で即時失効する。`revalidateTag(_, "max")` だと再取得で旧値が返り、入力済み件数が変わらなかった。
- 保存に失敗したら入力した値を残し、入力欄に `aria-invalid` を付けて、直下に「保存できませんでした。入力した内容は残っています。もう一度「保存」を押してください。」と出す。Action の文は「再読み込み」を勧めることがあり、そのまま出すと入力が消える操作へ誘導するため、カード側の文は値を控えてから再読み込みするよう添える。

## キー操作

| キー | Input | Textarea |
| --- | --- | --- |
| Enter | 保存 (`<form>` の送信。IME の変換確定では送信されない) | 改行 |
| Ctrl / ⌘ + Enter | — | 保存 |
| Escape | 未保存の変更があれば取消 | 同左 |
| Tab | 次の操作へ (保存 → 取消 → 次の項目)。値は捨てない | 同左 |

IME の変換中 (`isComposing`、Safari が変換確定の Enter で返す `keyCode === 229`) は保存も取消もしない。判定は `readFieldKeyCommand` (`basic-info-field-model.ts`)。

## 狭い幅

375px でも保存・取消は入力欄の直下に収まり、モバイルでは 44px の操作領域を保つ (`Button` の `size="sm"`)。
カテゴリの見出しは、件数と未保存の表示を語の途中で折らずに次の行へ送る。
「根拠・詳細」の開閉もモバイルでは 44px の高さを持つ。

## 検証

- `lib/domain/__tests__/basic-info-trust.test.ts`: 信頼度の境界 (0・49・50・69・70・80・81・100)、未入力、スコア欠落、範囲外・非有限値。
- `app/(main)/stores/[id]/_components/__tests__/basic-info-field-model.test.ts`: IME・キー操作・変更判定・入力欄の種類・由来・日時。
- `app/(main)/stores/[id]/_components/__tests__/basic-info-fields-card-render.test.tsx`: 見出しと冒頭の文、編集ボタンが無いこと、空欄に信頼度を出さないこと、3 段階の表示。
- `lib/actions/__tests__/basic-info-actions.test.ts`: `updateTag` での即時失効、手で直した値が元の確信度・出典を引き継がないこと。
- `e2e/store-basic-info-inline-edit.spec.ts`: 変更した項目だけの保存・取消、Tab で値を捨てないこと、取消・Escape、保存中の二重送信防止、再読み込み後の値、空欄保存、Ctrl+Enter と IME、保存失敗、375px / 1280px で保存・取消が入力欄と重ならないこと。

本番データでの確認では保存せず、未保存の変更は取消する。
