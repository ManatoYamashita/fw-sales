# 営業状態の用語と、店舗名に書かれた営業メモの移行 (#297)

## 状態の軸と呼び名

店舗には状態の軸が 2 本ある。画面ごとに呼び名がずれていたため (#297)、次の 2 語に統一した。

| 呼び名 | 意味 | 値 | 書き込み先 |
|---|---|---|---|
| **営業状態** | 営業の結果。一覧で最優先に出す | 受注（契約）/ 失注（ロスト）/ 見積提出 / 継続追客 / 初回接触 / アポ取得済み / 調査済み・未営業 / 未調査・未営業 | 営業記録 (deals) の状態から自動で決まる |
| **調査段階** | 調査・架電の進み具合 | 未調査 / 調査済み / 架電済み | 店舗詳細の上部で変更 (営業記録を追加すると架電済みへ自動昇格) |

- 営業状態は「最新の営業記録の状態」をそのまま使い、営業記録が無い店舗だけアポ取得日と調査段階から補う (`deriveCurrentSalesState`)。
- 以前あった絞り込みの「最新の営業状態」は営業状態と重複していたため外した。URL の `deal=` は互換のため解釈を続け、適用中チップ「最新の営業記録」から解除できる。
- 一覧の列は 営業状態 (コンテナ 778px 以上) → 調査段階 (874px 以上) の順に出る。狭幅カードも営業状態を先に置く。

## 失注と再アプローチ

失注の営業記録には **失注理由** と **再アプローチ** (再アプローチ可 / 再アプローチ不可 / 未判断) を記録できる。
一覧では失注のバッジの下に再アプローチ可否が出て、失注理由はマウスを重ねると読める。

現場の略語との対応の目安:

| 店舗名に書かれていた例 | 記録先 |
|---|---|
| 「Rアポ」「Rアポ・不通差し戻し」 | 営業記録: 失注 + 再アプローチ可 (次回アクションに再アポの予定日) |
| 「確バツ」「各バツ」「アプ即否」 | 営業記録: 失注 + 再アプローチ不可 |
| 「ハマロスト」「せロスト」 | 営業記録: 失注 + 失注理由 |
| 「7月24日NEW」「3月OPen」 | 顧客共有メモ (開業日などの継続情報) |

略語の意味は人によって揺れるので、移す前に書いた本人へ確認すること。

## 店舗名に書かれたメモを移す手順

1. 対象の一覧を出す (読み取りのみ。本番 DB を読むので `.env.local` の `DATABASE_URL` を使う)。

   ```bash
   pnpm db:list-name-memos
   ```

   店舗 ID / 現在の店舗名 / メモ / 店舗名の候補 / 同名の別店舗 が Markdown の表で出る。
   「同名の別店舗」に ID が出た行は、`（Rアポハマロスト）炉端ジュン` と `炉端ジュン` のような二重登録の疑いがある。

2. 店舗ごとに店舗詳細を開く。見出しの下に「店舗名に営業メモ「…」が含まれています」と案内が出る。
3. 営業進捗タブでメモの内容を営業記録 (失注理由・再アプローチ) か顧客共有メモへ書き写す。
4. 案内の「店舗名を「…」に直す」を押すと、候補が入った編集フォームが開く。確認して保存する (自動では保存しない)。
5. 二重登録だった場合は、営業記録を片方へ寄せてから不要な方を削除する (削除は管理者のみ)。

検出は `lib/domain/store-name-memo.ts` の `splitStoreNameMemo` が担う。店舗名の**先頭**の括弧書き (全角・半角・【】・［］) だけを対象にし、`(株)` などの法人格や、支店名のような途中・末尾の括弧は拾わない。
