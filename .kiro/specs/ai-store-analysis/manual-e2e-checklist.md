# 手動 E2E チェックリスト — `ai-store-analysis`

このチェックリストは Phase 7.3 の成果物。`/stores/new` の URL 解析→AI 分析→保存→
復元 の Golden Path とエッジケース 5 種、個人店バッジ表示の正常確認までを
ブラウザで手動確認するための手順を提供する。

実 API キー(`GEMINI_API_KEY`)が設定されていれば AI 分析機能の動作確認まで可能。
未設定環境でも UI 抑止(disabled + tooltip)は確認できる。

関連: `requirements.md` §1.4, §2.6, §2.7, §4.4, §5.2, §6.3, §6.4 / `tasks.md` 7.3

---

## 事前準備

- [ ] `.env.local` に `DATABASE_URL` を設定(または `USE_MOCK_DB=true`)
- [ ] (任意)`.env.local` に `GEMINI_API_KEY` を設定 — AI 分析機能を実 API で確認したい場合
- [ ] `pnpm install` 完了
- [ ] `pnpm dev` で localhost 起動

---

## Golden Path: URL 読込 → AI 分析 → 編集 → 保存 → 復元

### 1. 新規登録画面 `/stores/new` を開く

- [ ] 「店舗を登録」ヘッダが表示される
- [ ] 「URL から自動入力」パネルが先頭に表示される
- [ ] 「基本情報」「WEB資産・連絡先」「提案候補・営業メモ」「AI 分析」のカードが順に並ぶ
- [ ] (`GEMINI_API_KEY` 未設定環境のとき)[AI で分析] ボタンが disabled で「GEMINI_API_KEY が未設定のため無効」のテキストが表示される

### 2. 食べログ URL を URL Import Panel に貼り付けて [読込] 押下

例: `https://s.tabelog.com/kanagawa/A1405/A140504/14096697/`(導楽)

- [ ] 「読込中…」ローディング状態に遷移、その後成功 toast「N 項目中 M 項目を取得」
- [ ] 「基本情報」の 店舗名・都道府県・市区町村・住所・業態・運営者名 に値が自動入力される
- [ ] 「WEB資産・連絡先」の Google マップ URL・公式サイト・電話番号・口コミ件数・口コミ平均 に値が入る
- [ ] 各入力欄の **背景色グラデーション**(緑〜黄〜赤)が信頼度に応じて表示される
- [ ] (運営者付きページのとき)「運営者名」欄に法人名 / オーナー名が入り背景色付き
- [ ] 「運営者種別」セレクタは "未設定" のまま(URL 解析では判別不可)

### 3. (`GEMINI_API_KEY` 設定済の場合)[AI で分析] 押下

- [ ] CTA ボタンが pending 状態 (「AI 分析中…」) になり disabled
- [ ] 他のフォームフィールドは引き続き編集可能
- [ ] 数秒〜30 秒で完了、5 エリア(強み Markdown / 弱み Markdown / グルメサイト課金 / GBP / 架電スクリプト)が表示される
- [ ] 各エリアに **信頼度の背景色グラデーション** が適用されている
- [ ] (信頼度 < 50 のフィールドが含まれる場合)「⚠ 要確認」ラベルが該当エリアに表示される
- [ ] 架電スクリプトエリアに「クリップボードへコピー」ボタンが表示される

### 4. 結果フィールドを 1 箇所手で編集する

- [ ] 編集したエリアの 背景色が解除される(編集マーカー)
- [ ] 他のエリアの背景色は残る

### 5. 「クリップボードへコピー」を押す

- [ ] toast 「架電スクリプトをコピーしました」
- [ ] OS クリップボードに架電スクリプト全文がコピーされている(別エディタ / メモ帳でペーストして確認)

### 6. 「運営者種別」を 「個人店」 に変更

- [ ] セレクタが "個人店" になる

### 7. [登録する] 押下

- [ ] toast 「登録しました」が表示される
- [ ] `/stores/<id>` 詳細画面に遷移する

### 8. 詳細画面の確認

- [ ] 店舗名の隣に **個人店バッジ**(緑・User アイコン・「個人店」)が表示される
- [ ] 「基本情報」カードに「運営者種別: 個人店」「運営者名: <設定値>」が表示される

### 9. 一覧画面 `/stores` に戻る

- [ ] 一覧テーブルの「店舗名」セルで、登録した個人店の隣に個人店バッジが表示される

### 10. 詳細画面の [編集] ボタン → 編集 form へ

- [ ] 「基本情報」「WEB資産・連絡先」「提案候補・営業メモ」「AI 分析」の構造が新規登録画面と同じ
- [ ] 「運営者種別」が "個人店"、「運営者名」も登録時の値が復元されている
- [ ] AI 分析パネル下部の 5 エリアに **登録時の AI 結果が復元** され、信頼度の背景色も復元時に表示される
- [ ] 編集モードでも [AI で分析] CTA は機能する(`isApiKeyConfigured` 経由)

## エッジケース 5 種

### Edge 1: API キー未設定

`.env.local` から `GEMINI_API_KEY` を一時的に削除またはコメントアウトして `pnpm dev` を再起動。

- [ ] `/stores/new` 開いたとき、[AI で分析] CTA が **disabled** 表示
- [ ] CTA 隣の文言「GEMINI_API_KEY が未設定のため無効」が表示される
- [ ] tooltip(マウスホバーで)「環境変数 GEMINI_API_KEY が未設定のため AI 分析は無効です。」が表示される
- [ ] 他のフォーム機能(URL 読込、登録、保存)は正常に動作する

### Edge 2: タイムアウト(60 秒)

API キー有効環境で、ネットワークを意図的に遅延させる(DevTools の Throttling で「Slow 3G」or 「Offline」)。

- [ ] [AI で分析] 押下後 60 秒経過すると失敗 toast「AI 分析がタイムアウトしました(60 秒)」
- [ ] フォーム値は **変更されない**(URL から取得した値などはそのまま)
- [ ] [AI で分析] ボタンが **即時再有効化** される(再試行可能)

### Edge 3: レートリミット(同一 storeId 6 回連続)

編集画面で同じ店舗に対して [AI で分析] を 6 回連続で押す(Edge ケースなので時間内に短時間で連打)。

- [ ] 6 回目の押下時に toast「この店舗の連続分析を制限中です(10 分以内に 5 回以上)」
- [ ] CTA は引き続き押せる(クライアント側 disabled でない)が、push しても rate limit エラーが返る

### Edge 4: 自由追加指示 500 字超

「追加指示」textarea に 600 字程度の文字列を貼り付ける。

- [ ] `maxLength=500` 属性で **入力時点で 500 字でカットされる**(コピペでも 500 字に切り詰め)
- [ ] 字数カウンタ「500 / 500 字」が右下に表示される

### Edge 5: 未保存遷移警告

[AI で分析] が成功した直後、[登録する] を押さずにブラウザのタブを閉じようとする(または別 URL に navigate)。

- [ ] ブラウザ標準の確認ダイアログ(離脱しますか?)が表示される
- [ ] [キャンセル] でその場に留まる
- [ ] [OK] で離脱する

## 既知の挙動・OUT 項目(本 spec で実装しないもの)

- soft navigation(`<Link>` クリックや `router.push`)経由の離脱は警告されない(hard nav のみ MVP、研究.md Topic 5)
- AI 分析結果のキャッシュは無し → 同一 URL でも 2 回目分析もコスト発生
- 部分再生成(「強みだけ再生成」)は無し → 全 5 エリアを 1 回で再生成
- 分析履歴は無し → 常に上書き
- コスト/トークン数表示は無し(Req 6.5)
